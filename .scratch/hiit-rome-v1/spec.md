# Spec: hiit-rome v1

Status: ready-for-agent

Vocabulary follows [GLOSSARY.md](../../GLOSSARY.md). Respect [ADR 0001](../../docs/adr/0001-device-local-data-no-backend.md) (device-local data, no backend) and [ADR 0002](../../docs/adr/0002-sveltekit-static-spa.md) (SvelteKit static SPA, framework-free timer engine). Deferred work is tracked in [docs/roadmap.md](../../docs/roadmap.md).

## Problem Statement

A trainer runs interval workouts (HIIT, Tabata, circuits) for themselves and a small circle of clients. They want the clarity of the Seconds Pro mobile app: a full-screen, color-coded timer that announces each interval. But they want it on a TV across the gym floor, driven from a laptop or tablet, not squinted at on a phone. Phone apps are hard to read at a distance and awkward to mirror. Generic browser timers can't express structured workouts (warm-up, repeated rounds of work/rest, rest between rounds, cool-down), don't speak, and lose their place when the browser hiccups. The trainer also needs to build workouts quickly, start one in a couple of clicks, and recover gracefully from real-world interruptions: a client needs water, the laptop sleeps, the tab reloads.

## Solution

An installable web app (PWA), designed for large landscape screens first, that turns a structured **Workout** into a readable **Session** on a TV.

- **Building.** Workouts are made of **Intervals** (each with a **Kind**: Warm-up, Work, Rest or Cool-down) arranged in **Groups** that repeat as **Rounds**, nesting up to two levels. They are built in an outline editor, generated by **Wizards** (HIIT, Tabata, Circuit, EMOM), or copied from **Samples** in the built-in **Library**.
- **Running.** In a Session, the whole screen takes the current Interval's color. It shows a huge remaining time, the Interval name and Kind, the Round position and the next Interval. The device's built-in voice speaks Interval names and **Warnings**, with beeps for the final seconds.
- **Controls.** Everything is driven from the keyboard or by tap and swipe. That covers pause/resume, next/previous, ±30 s, jump to any Interval, restart and end. A Session survives reloads and sleep by reopening paused exactly where it left off.
- **Countdown.** A standalone **Countdown** with five editable **Presets** covers simple timing needs.
- **Data.** Everything lives on the device. Workouts move between devices by share link and are protected by a backup file.

## User Stories

### Running a Session: display

1. As a trainer, I want the whole screen to take the current Interval's color, so that everyone in the room knows whether it's Work or Rest without reading anything.
2. As an athlete across the gym, I want the remaining time to be the largest element on screen (about half its height), so that I can read it from 5+ meters away.
3. As an athlete, I want to see the current Interval's name (e.g. "Burpees") in large text, so that I know which exercise to do.
4. As an athlete, I want the current Interval's Kind shown as text ("WORK", "REST"), so that color is never the only signal (color-blind users).
5. As an athlete, I want an "Up next" rail beside the timer listing the next five Intervals (each with a color chip, name and duration, the first one largest), so that I can see what's coming without waiting for a Warning.
6. As an athlete, I want to see my Round position (e.g. "Tabata 2 of 4" and "Round 5 of 8", one per line) at the foot of the rail, so that I know how far through the Workout I am.
7. As a trainer, I want unnamed outer Groups left out of the Round header, while the innermost Group always shows "Round X of Y", so that the header stays readable.
8. As a trainer, I want named Groups shown by name in the header (e.g. "Tabata 2 of 4"), so that the structure I designed is visible.
9. As an athlete, I want to see total time remaining in the Session (e.g. "14:32 left") at the foot of the rail, so that I can pace my effort.
10. As an athlete, I want a progress bar for the current Interval under the digits, so that I can sense elapsed time at a glance.
11. As an athlete, I want the remaining-time digits to pulse visibly in the final 3 seconds, so that I notice the transition even when the gym is too loud to hear beeps.
12. As a trainer, I want the display to work in landscape (rail on the right) and portrait (rail below the timer), so that it suits a TV, a propped tablet or a monitor.
12a. As an athlete, I want the first "Up next" item to wrap a long name onto two lines rather than truncate it, while later items may truncate, so that the next exercise is always fully readable.
12b. As an athlete, I want the Kind label hidden when the Interval's name already says it (e.g. an Interval named "Cool-down"), so that the screen never reads "COOL-DOWN Cool-down".
12c. As an athlete, I want the rail to show a single "Finish" row during the final Interval, so that I know this is the last effort.
13. As a trainer, I want text colors chosen automatically to be readable on each background color, so that digits are never invisible (e.g. navy on yellow).
14. As a trainer, I want the screen to stay awake during a Session, so that the TV doesn't dim or sleep mid-Workout.
15. As a trainer, I want to put the Session into browser fullscreen with one key, so that no browser chrome appears on the TV.
16. As a trainer, I want the Lead-in shown on a neutral navy screen with "Get ready" and the rail listing the first Intervals, so that the class knows we're about to begin.
17. As a trainer, I want a paused Session to show a clear "PAUSED" state on a neutral navy screen while keeping the current Interval visible, so that nobody thinks the clock is running.

### Running a Session: controls

18. As a trainer, I want to start a Session with the Space key, so that I can begin from across the room with a wireless keyboard.
19. As a trainer, I want a Lead-in countdown before the first Interval (length set per Workout, default 10 s, may be 0), so that the class has time to get into position.
20. As a trainer, I want Space to pause and resume, so that I can handle interruptions instantly.
21. As a trainer, I want a short 3-second Lead-in when resuming from pause (on by default, can be turned off in Settings), so that nobody is caught cold mid-Interval.
22. As a trainer, I want → to jump to the start of the next Interval, so that I can skip something we don't need.
23. As a trainer, I want ← to restart the current Interval if more than 3 s have elapsed, otherwise go to the previous Interval, so that it behaves like a music player.
24. As a trainer, I want to add or remove 30 seconds on the current Interval (↑ / ↓), so that I can adapt to the class on the fly without editing the Workout.
25. As a trainer, I want ±30 s changes to affect only this Session, never the saved Workout, so that one-off adjustments don't pollute my plan.
26. As a trainer, I want removing 30 s from an Interval with less than 30 s left to end that Interval and move on, so that the control never produces negative time.
27. As a trainer, I want to open a list of every Interval in the Session, grouped by Group and Round, and jump to any of them, so that I can restart a Round or go back to a specific Tabata.
28. As a trainer, I want to restart the whole Session from the beginning (including the Lead-in) from the pause screen, with a confirmation, so that I can start over without leaving the screen.

32. As a trainer on a tablet, I want a small auto-hiding control bar with every action, so that all controls are reachable by touch.
33. As a trainer, I want pressing → on the last Interval to complete the Session, so that skipping always moves forward.

### Running a Session: resilience

34. As a trainer, I want the Session to keep accurate time even if the browser throttles or briefly suspends the page, so that the clock never drifts.
35. As a trainer, I want the Session to keep running and announcing Cues while I switch to another app or tab (e.g. a music player), so that I can manage music during a Workout.
36. As a trainer, I want the app to detect that the device slept and automatically pause at the last known second, so that time "spent asleep" isn't counted as exercise.
37. As a trainer, I want an unfinished Session to be offered back to me ("Resume where you left off?") after a reload, crash or reopen, so that I don't lose my place.
38. As a trainer, I want a recovered Session to come back paused at the exact second I left, so that it never silently runs while I was away.
39. As a trainer, I want to discard a recovered Session, so that I can start fresh instead.

52. As a trainer, I want to create a blank Workout and give it a name, so that I can build a custom routine.

58. As a trainer, I want to set a Group's name, number of Rounds and "Skip last rest" toggle, so that I can control how it repeats.
59. As a trainer, I want "Skip last rest" on by default, so that a Group's final Round doesn't end with a pointless Rest.

67. As a trainer, I want to set the Workout's Lead-in length and Cue overrides in a per-Workout settings panel, so that each Workout behaves as I need.
68. As a trainer, I want to start a Session directly from the editor, so that I can test what I've built.
69. As a trainer, I want to be prevented from starting a Workout with no Intervals, with a clear message, so that I don't launch an empty Session.

### Building Workouts: Wizards

70. As a trainer, I want a HIIT Wizard (Work, Rest, Rounds, Warm-up, Cool-down), so that I can generate a standard HIIT Workout in seconds.
71. As a trainer, I want a Tabata Wizard (Work 20 s, Rest 10 s, Rounds 8, number of Tabatas, rest between Tabatas, Warm-up, Cool-down), so that I can generate single or multi-Tabata Workouts.

### App and platform

107. As a trainer, I want to install the app to my device's home screen or dock, so that it opens like a native app.

## Implementation Decisions

### Architecture

- **Static SPA (ADR 0002).** SvelteKit with Svelte 5, `adapter-static` in SPA mode, no server-side rendering, no server routes and no form actions. Installable and offline-capable via `@vite-pwa/sveltekit`, with the app shell precached.
- **Device-local data (ADR 0001).** IndexedDB holds Workouts, Settings, Presets and saved Session state. There are no accounts, no network calls for data, and no analytics.
- **Framework-free engine.** The timer engine is plain TypeScript with no Svelte imports. Svelte components are a thin layer that renders the engine's view and dispatches user actions to it. Timing logic in components is a bug.
- **Single device, separable control.** v1 runs the display and controls on one device. The engine accepts actions as plain data and exposes its view as plain data, so a remote control can drive it later without engine changes.

### Modules

Each module is designed as a deep module: a small interface with substantial behavior behind it.

1. **Workout model.** The domain types (Workout, Group, Interval, Kind) plus validation and duration calculation.
   - A Workout has an id, name, a root sequence of items, Lead-in length, optional Cue overrides, a favorite flag, and created/last-used timestamps.
   - An item is either an Interval or a Group.
   - An Interval has a name, Kind, duration in whole seconds, and an optional color override (one of the palette tokens).
   - A Group has an optional name, a Round count, a "Skip last rest" flag (default on) and a sequence of items.
   - The model allows any nesting depth; the two-level limit is enforced by the editor only.
   - Limits: duration 1 s to 99:59; Rounds 1 to 99.
   - Empty Groups are allowed while editing, contribute nothing to the Timeline, and are flagged in the editor. A Workout whose Timeline is empty cannot be started.

2. **Timeline builder.** A pure function from Workout to Timeline. It flattens nested Groups into an ordered list of Timeline entries. Each entry carries:
   - the Interval (name, Kind, duration, resolved color and paired text color)
   - its start offset from the beginning of the Workout
   - its position path: for each enclosing Group, its name (if any), the current Round and the total Rounds

   **Skip last rest:** on a Group's final Round, if the flag is on, any Rest-Kind Intervals at the very end of that Round are dropped. This is applied recursively at every level. The Timeline's total duration is the source of truth for every "total duration" shown in the app (editor, Wizards, cards, Library).

3. **Session engine.** A deterministic state machine. It is created from a Timeline and effective Cue settings, and is advanced by actions, each stamped with a time. It never reads the clock itself.
   - **Actions:** start, pause, resume, next, previous, adjust (+30 s / −30 s), jump to entry, restart, end, tick.
   - **Statuses:** idle, Lead-in, running, paused, resume Lead-in, completed, ended.
   - **Timekeeping is timestamp-based.** Position comes from accumulated running time plus (now − time running resumed), never from counting ticks. ±30 s adjustments are stored as per-entry offsets for this Session only.
   - **Previous:** restarts the current Interval if more than 3 s have elapsed, otherwise goes to the previous entry; on the first entry it restarts that entry.
   - **Next:** on the final entry, completes the Session.
   - **−30 s:** if less than 30 s remain, the current Interval ends and the next one starts.
   - **Jump:** goes to the start of the chosen entry and keeps the current running or paused state.
   - **Restart:** returns to idle and starts again with the Lead-in.
   - **Sleep detection:** if a tick arrives more than 10 s after the previous one, the engine treats it as a suspension. It auto-pauses at the last tick's position and does not count the gap.
   - **View (a pure function of state and now):** status; current entry; the next five upcoming entries (for the "Up next" rail; during the Lead-in these start at the first entry); remaining and elapsed time in the current Interval; total remaining time; Interval progress (0 to 1); header labels (named Groups as "Name X of Y", the innermost Group as "Round X of Y" when unnamed, unnamed outer Groups omitted); and the background and text colors to display.
   - **Cues due:** each tick returns the Cues whose scheduled moment fell between the previous tick and this one, so a throttled tick still emits what was due. Cues more than 2 s stale are dropped rather than played late. The final-seconds beeps for the current Interval are reported ahead of time, so the audio layer can schedule them precisely.
   - **Serialization:** the engine state serializes to and restores from plain data, for Session recovery. A restored Session is always paused.
   - **The Countdown is not a separate engine.** It is a Session over a one-entry Timeline with Countdown-specific Cue settings and end behavior.

4. **Cue rules (part of the Session engine).** These turn the Timeline and effective Cue settings into scheduled Cues. Each Cue has a moment, a type (speech, beep, final tone or chime) and, for speech, the text.
   - **Interval start:** speak the Interval name; an unnamed Rest speaks "Rest".
   - **Warning:** at N seconds before an Interval ends (default 10), speak "Next: \<next name\>". On the final Interval, speak "Last N seconds" instead.
   - **Merge rule:** if N is at least the Interval's duration, the Warning merges into the start announcement as "\<name\>. Next: \<next name\>."
   - **Final seconds:** beeps at 3, 2 and 1 s, and a distinct higher tone at 0.
   - **Halfway:** speak "Halfway" on Intervals of 30 s or longer (off by default).
   - **Completion:** speak "Workout complete" with a chime.
   - **Lead-in:** beeps over its final seconds.
   - **Countdown:** final-seconds beeps, an optional Warning ("1 minute remaining", default on, only when the Countdown is longer than 1 minute), and a chime three times at zero, after which the view shows a flashing "TIME" until dismissed.
   - **Effective settings:** the global defaults overlaid with the Workout's overrides.

5. **Wizards.** Pure functions from Wizard parameters to Workout. Each Wizard proposes a default name (e.g. "Tabata ×4 (20/10)"). Warm-up and Cool-down are omitted when set to 0.
   - **HIIT:** Warm-up → Group[Work, Rest] × Rounds → Cool-down. The Work Interval is named "Work" unless an exercise name is given.
   - **Tabata:** Warm-up → (if more than one Tabata) Group "Tabata" × count [unnamed Group[Work, Rest] × Rounds, Rest "Between Tabatas"]; otherwise just the inner Group → Cool-down.
   - **Circuit:** Warm-up → Group[Ex1, Rest, Ex2, Rest, …, ExN, Rest "Round rest"] × Rounds → Cool-down. There is no Rest between the last exercise and the Round rest, and exercise names become Work Interval names.
   - **EMOM:** Warm-up → Group[Ex1 60 s, …, ExN 60 s] × Rounds → Cool-down, all Work-Kind.
   - **Finishing:** "Start now" saves then starts; "Save & edit" saves then opens the editor. The output carries no link back to the Wizard.

6. **Library.** A static, read-only collection of about 10 Samples bundled with the app, covering beginner, intermediate and advanced levels across HIIT, Tabata, Circuit and EMOM, plus at least two hand-built Samples that use named nested Groups. Samples are drafted by the implementer and reviewed by the user before release. Starting a Sample runs it directly. "Add to my Workouts" copies it with a fresh id.

7. **Workout store.** Persistence and querying over IndexedDB, covering:
   - CRUD for Workouts, Favorites, the last-used timestamp (updated when a Session starts), and search by name (case-insensitive substring)
   - sorting by recent, name or duration, with Favorites pinned first
   - Settings and Presets
   - the single saved active Session (written on every state-changing action and at least every 5 s while running, and cleared on completion, end or discard)
   - the last-backup timestamp

   The stored data carries a schema version from day one, with forward migrations run on open. The store requests persistent storage on first launch. A saved Session older than 12 hours is discarded instead of offered for recovery.

8. **Transfer.** Two parts:
   - **Share-link codec.** Workout → URL whose fragment holds a versioned, compressed (deflate + base64url) serialization of the Workout's content, without its id, favorite flag or timestamps. URL → Workout, with version checks and validation; invalid or unknown-version links show a friendly error.
   - **Backup.** Export produces one JSON file with schema version, export date, all Workouts, Presets and Settings. Import validates, migrates if needed, then merges:
     - Workouts with the same id and identical content are skipped.
     - Otherwise they are added with a new id, with " (2)" (then " (3)", and so on) appended on a name clash.
     - Settings and Presets are replaced only after an explicit confirmation.

     A successful export updates the last-backup timestamp.

9. **Platform adapters.** Thin, swappable boundaries around browser APIs, each with a fake for tests.
   - **Ticker:** drives engine ticks at least every 250 ms while visible.
   - **Cue player:** speech via the Web Speech API with a voice chosen from those on the device, and beeps, tones and chimes generated with Web Audio. Its audio context is unlocked on the first user gesture. Beeps announced ahead of time are scheduled on the audio clock for precision.
   - **Keepalive:** while a Session is active, a near-silent Web Audio source keeps the page exempt from aggressive background-tab timer throttling, so Cues continue while another app or tab is in front.
   - **Screen wake lock** and **Fullscreen.**

   The Cue player's interface (speak, beep, final tone, chime, list voices, select voice) is the seam a future music source would follow.

10. **UI routes.** Home (My Workouts, Library, Countdown, New Workout, Wizard), Workout editor, Wizard picker and forms, Sample preview, Session display (with Interval list for jumping, pause screen, summary), Countdown, Settings (voice, global Cue defaults, resume Lead-in toggle, Presets, Countdown color, backup and import, last backup), and share-link import preview.

### Interaction specifics

- **Keyboard:** Space starts, pauses and resumes; → next; ← previous; ↑ +30 s; ↓ −30 s; J opens the Interval list; R restarts (from the pause screen, confirmed); Esc ends (confirmed); F toggles fullscreen.
- **Touch:** tap anywhere pauses or resumes; swipe left or right for next or previous; a control bar with every action appears on touch and hides after 3 s of inactivity.
- **Resume Lead-in:** 3 s on the navy screen with beeps. Global setting, default on.
- **Final-seconds pulse:** shown as a color flash rather than motion when the user prefers reduced motion.
- **Session screen layout (decided by prototype, variant B "Side rail").**
  - **Main area (left, about two-thirds of the width):** in the current Interval's color, it shows the Kind label, the Interval name, the remaining time (sized at about min(44vh, 19vw)), and the Interval progress bar.
  - **Right rail (about one-third):** always neutral navy. It shows "UP NEXT" with the next five entries; the first item is largest and wraps, and the rest are dimmer and truncate. At its foot are the Round header lines and the total time left (falling back to the Workout name when the current Interval is outside any Group).
  - **Portrait:** the rail stacks below the main area.
  - **Digit font:** not yet chosen (the prototype offered System sans, Inter, Oswald, Bebas Neue and Roboto Mono). Use the system sans with tabular numbers until the user picks one.
- **Session summary:** elapsed time, number of Intervals completed, and total Work-Kind time. Nothing is persisted (no history).
- **One active timer:** starting a Session or Countdown while another is active asks to end the current one first.

## Testing Decisions

- **What a good test is.** It exercises external behavior through a seam the app itself uses: given inputs and a controlled clock, assert on the view, the Cues emitted, or the stored or transferred data. Tests must not reach into internal state, private helpers or Svelte component internals. They should survive any refactor that keeps behavior the same.
- **Seam A: Session engine (primary).** Vitest. Build Workouts (by hand and via Wizards), produce Timelines, create a Session, dispatch timestamped actions with a fake clock, and assert on the view and Cues due. Coverage:
  - Nested Groups and "Skip last rest" at both levels, including the 4-Tabata example and totals
  - Header labels for named and unnamed Groups
  - Lead-in and resume Lead-in
  - Pause, resume, next, previous (the 3 s rule and the first-entry edge), ±30 s (including −30 s with less than 30 s left), jump, restart, end, and completion via next on the last entry
  - Sleep detection (a gap over 10 s auto-pauses at the last position)
  - Throttled ticks still emitting due Cues, and stale Cues dropped
  - Warning and start merging, the final-Interval Warning, Halfway eligibility, and Cue overrides over defaults
  - Serialize and restore (always paused)
  - Countdown behavior: Presets, Warning only when longer than 1 min, chime ×3, the TIME state
  - Wizards: each one's structure, names and totals
  - The palette contrast check
- **Seam B: Workout store and Transfer.** Vitest with an in-memory IndexedDB fake. Coverage:
  - CRUD, Favorites pinning, search and sort
  - last-used updates
  - the saved-Session lifecycle and the 12-hour expiry
  - schema-version migration on open
  - share-link round trip (a Workout survives encode and decode), and rejection of corrupt or unknown-version links
  - backup round trip, merge rules (identical skipped, " (2)" suffixing, Settings and Presets replaced only on confirmation) and the last-backup timestamp
- **Seam C: Browser smoke (thin).** Playwright against the built static app, with the Cue player swapped for a recording fake and the page clock controlled. A handful of tests:
  - keyboard drives a Session start to finish, the background color changes per Kind, and the recorded Cues include the expected announcements
  - Wizard → Start now
  - a reload during a Session offers recovery, which comes back paused
  - opening a share link shows the preview and "Add to my Workouts" works
- **Prior art.** None; this is a greenfield repository. These tests establish the conventions.

## Out of Scope

See [docs/roadmap.md](../../docs/roadmap.md) for the full list with reasons. In summary:

- Music integration of any kind. v1 is "play alongside" only; Spotify Workout music with ducking is the first follow-up.
- Imported audio files, and pre-recorded or AI voices.
- Accounts, cloud sync and any backend.
- Phone-as-remote. The engine is ready; there is no UI or sync.
- Workout history and logging.
- The Pyramid Wizard, re-runnable Wizards, reusable snippets, folders, and multi-Workout bulk operations.
- Groups nested deeper than two levels in the editor.
- Multiple languages (English only), and watch, heart-rate or health integrations.
- A palette beyond the five colors.
- Hosting and deployment setup. The user will choose a host after a working proof of concept.

## Further Notes

- **Prototype outcome (2026-10-01).** A throwaway Session-screen prototype compared four layouts: A, the spec layout; B, a side rail with an upcoming list; C, maximum digits with a Next band; and D, a progress ring with Round dots. The user chose **B**; see "Session screen layout" under Interaction specifics. The prototype lives on the throwaway git branch `prototype/session-screen`, not on `main`.
- **The palette is tentative.** The user may change it. It lives in one token set; when it changes, re-run the contrast check and re-pick paired text colors.
- **iOS background audio is fragile.** If the phone-first pivot happens, background Cues on iPhone are best-effort; the timestamp-based clock guarantees correct position on return.
- **Keepalive audio is the main platform risk.** Validate early on Chrome, Safari and Firefox on the target laptop. If a browser still throttles hidden tabs, Cues may drop while another tab is in front, but timekeeping stays correct.
- **The Samples need user review** before release.
- **No issue tracker is configured.** The spec follows the local-markdown convention in `.scratch/`. The user can run `/setup-matt-pocock-skills` to formalize this for other skills.
